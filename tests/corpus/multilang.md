# Инструкция по API-интеграции

Раздел содержит легитимное сочетание кириллицы и латиницы: технические
идентификаторы, аббревиатуры и имена переменных на латинице при основном тексте
на русском языке. Проверяет, что §7-проверка нечитаемых символов не ложно
срабатывает на смешанное содержимое.

## Точки входа

Для конвертации используйте метод POST на endpoint `/api/v2/convert`. Параметры
передаются в теле запроса в формате JSON. Ответ содержит поле `status` (строка
`ok`, `bad` или `failed`) и поле `result_path` с путём к выходному файлу.

Пример тела запроса:

```json
{"source_path": "/data/input.pdf", "output_dir": "/data/out", "method": "pdf"}
```

## Переменные окружения

До запуска инструмента должны быть установлены переменные среды:

| Переменная | Тип | По умолчанию | Описание |
|---|---|---|---|
| `RAW2MD_LOG` | string | `INFO` | Уровень журналирования |
| `RAW2MD_TEMP` | path | `/tmp/raw2md` | Рабочая папка |
| `RAW2MD_MAX` | int | `100` | Максимум файлов в пакете |

## Коды возврата

Инструмент возвращает стандартные exit codes: код 0 — успех, код 1 — частичный
успех в пакете (один или несколько файлов не обработаны), код 2 — ошибка
конфигурации, код 3 — недоступность зависимости (pandoc, marker или djvulibre),
код 4 — нет результата для единственного файла.

## Форматы и аббревиатуры

Поддерживаемые форматы: PDF (Portable Document Format), DOCX (Office Open XML),
DjVu, Markdown. Все аббревиатуры приводятся на латинице — общепринятая практика
в технической документации. Термины OCR (Optical Character Recognition), API
(Application Programming Interface) и CLI (Command Line Interface) употребляются
без перевода. Флаги командной строки — `--output-dir`, `--no-yaml`,
`--skip-existing`, `--overwrite` — также остаются в исходной форме.
